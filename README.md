# Интерактивный симулятор картографических проекций

Веб-приложение, наглядно показывающее связь между 3D-глобусом Земли и плоской 2D-картой.
Главная фича — визуализация того, как математика проекции переносит точки с поверхности
Земли на вспомогательную фигуру (цилиндр, конус или плоскость) и как при этом искажаются
формы, площади и расстояния.

Поддерживаются 7 проекций в трёх семействах — цилиндрическое, коническое,
азимутальное. Реализованы ровно те проекции, которые можно наглядно показать
в 3D-сцене как перенос точек глобуса на разворачиваемую поверхность:
цилиндрические (равнопромежуточная, Меркатор), конические (конформная Ламберта,
равновеликая Альберса) и азимутальные перспективные (гномоническая,
стереографическая, ортографическая).

## Технологии

- **Vite 6** + **React 19** + **TypeScript 5.8** (строгий режим, без `any` в пропсах)
- **Tailwind CSS v4** — стилизация (тёмная «космическая» тема)
- **Zustand** — глобальное состояние
- **three** + **@react-three/fiber** + **@react-three/drei** — 3D-сцена
- **d3-geo**, **topojson-client** — 2D-карта и проекционная математика
- **Vitest** + **React Testing Library** + **jsdom** — тесты

Приложение полностью клиентское (SPA), без бэкенда и внешних API.

## Быстрый старт

```bash
npm install      # установка зависимостей
npm run dev      # дев-сервер (http://localhost:5173)
```

Откройте http://localhost:5173. Слева сверху — панель управления, слева снизу — 3D-глобус
с лучами проекции, справа (2/3 экрана) — плоская 2D-карта.

## Архитектура

Всё состояние хранится в одном сторе; UI, 2D- и 3D-компоненты только читают из него
и вызывают его экшены.

| Модуль                       | Роль                                                                 |
| ---------------------------- | -------------------------------------------------------------------- |
| `src/store/useAppStore.ts`   | Единый источник правды: параметры проекции, геоданные, экшены        |
| `src/utils/projectionMapper.ts` | Маппинг `(family × distortion)` → конкретная D3-проекция          |

| `src/components/Map2D.tsx`   | Адаптивная SVG-карта: проекция подгоняется под контейнер (`fitProjectionToView`), чтобы глобус всегда заполнял доступную площадь с небольшими отступами; гратула, берега, индикатрисы Тиссо, кнопки-тумблеры в углу (Тиссо, Сетка, границы…) |
| `src/components/ControlPanel.tsx` | Панель управления: параметры проекции, слайдеры, пресеты точки касания |
| `src/components/GlobeScene.tsx` | 3D-сцена, компонует `Globe` / `AuxSurface` / `IntersectionDisks` / `LightSource` / `Rays`, `CutLine` и `TouchPointPin` |
| `src/components/Globe.tsx`   | Прозрачный глобус с неоновыми 3D-линиями берегов (без гратулы — сетка только на 2D-карте) |
| `src/components/AuxSurface.tsx` | Вспомогательная поверхность — прозрачный неоновый каркас (цилиндр / конус / плоскость) |
| `src/components/IntersectionDisks.tsx` | Полые белые неоновые кольца в местах реального пересечения поверхности с глобусом (0, 1 или 2 окружности) |
| `src/components/LightSource.tsx` | Жёлтый светящийся «источник света» (точечная лампа для азимутальных, вершина конуса для конических; для цилиндрических не рисуется) |
| `src/components/Rays.tsx`    | Жёлтый веер лучей проекции от источника к вспомогательной поверхности |
| `src/constants/designTokens.ts` | Общая палитра `NEON_BLUE` / `NEON_ORANGE` / `BG` и производные  |
| `src/constants/geometry.ts`  | Общие числовые константы (`MAP_SCALE`, `VIEW_CENTER_*`, `RADIUS`, `RAY_COUNT`, …) и `standardParallelDeg` |
| `src/store/selectors.ts`     | `useProjectionParams()` — мемоизированный селектор стора |
| `src/components/ui/`         | Общие иконки (`icons.tsx`), стили (`styles.ts`), подписи (`labels.ts`), `ParamSlider`, `PresetChips` |
| `src/App.tsx`                | Компоновка из трёх панелей + загрузка геоданных при монтировании   |

### Математическое ядро

`getD3Projection(params)` (где `params` — объект `ProjectionParams` из стора)
возвращает D3-проекцию по жёсткой таблице:

| Семейство (`family`) | Conformal (равноугольная) | EqualArea (равновеликая) | Equidistant (равнопромежуточная) |
| -------------------- | ------------------------- | ------------------------- | --------------------------------- |
| `cylindrical`        | секущая Меркатора (φ_s)   | равновеликая (по φ_s)     | равнопромежуточная (по φ_s)       |
| `conic`              | ConicConformal            | ConicEqualArea            | ConicEquidistant                  |
| `azimuthalPerspective` | по источнику света      | —                         | —                                 |

Вращение использует **отрицательные** знаки: `.rotate([-(lambda0), -phiOrigin, rotZ])`.
`rotZ = -gamma` для азимутального семейства (поворот карты вокруг точки касания),
но `rotZ = 0` для **цилиндрического**. 2D-карта цилиндрических проекций — это **неподвижный
градуированный барабан**: сама проекция не несёт никаких поворотов (`rotate([0, 0, 0])`),
а Долгота/Параллель **перекатывают Землю внутри трубы** — истинным сферическим поворотом
`makeFrameRotation(lambda0, phiOrigin)` (= d3 `geoRotation([-lambda0, -phiOrigin])`), который
применяется к координатам данных **до** проекции. Благодаря этому карта — честная проекция:
выбранная центральная точка (λ₀, φ₀) всегда ложится на среднюю строку с **наименьшими
искажениями**, а содержимое дальше от неё растягивается к краям окна (южный полюс в центре ⇒
полюс почти в истинном масштабе, а бывший экватор, оказавшийся в ±90°, растянут огромно) —
карта никогда не просто «ездит». Поворот зеркалит матрицу побережий 3D-сцены
(`projectionRotationMatrix(-lambda0, -phiOrigin, 0)`); физический тест фиксирует их точное
совпадение, поэтому оба вида показывают одинаково перекатанный глобус. Лучи остаются
**статичным аппаратом**, пришитым к центральному меридиану сетки.
`lambda0` / `phiOrigin`
задают центральный меридиан / широту. `makeCylindricalProjection(distortion, scaleFactor)`
сохраняет выбранное свойство своим законом высоты со стандартной параллелью на контакте ±φ_s
(φ_s = arccos(`scaleFactor`)): равноугольная → секущая Меркатора, равновеликая → y ∝ sin φ /
cos φ_s, равнопромежуточная → y ∝ φ. Карта построена по **модели неподвижного барабана**: цилиндр и его
градуировка (сетка координат с полюсами у краёв окна) **неподвижны** — Map2D строит **одну**
fitted-проекцию на кадр и рисует через неё все слои; для цилиндрических эта проекция по построению
не несёт никаких поворотов, поэтому слой сетки автоматически остаётся неподвижной рамкой барабана;
**слой материков**
(вместе с границами стран и индикатрисами Тиссо) при каждом движении ползунков
**проецируется заново**: Долгота/Параллель перекатывают его через `makeFrameRotation`
(`geoBandClip.rotateFeatureCollection` / `rotatePolygon` применяют поворот к каждой
координате; Map2D делает это перед рисованием), поэтому материки по-настоящему огибают
барабан — при полюсе в центре географические меридианы/параллели изгибаются, тогда как
линейки самого барабана под ними остаются прямыми. Вертикальная координата **периодична**
в системе барабана: широта кадра заворачивается в полосу ±`CLIP_LAT` с периодом 2·`CLIP_LAT`,
поэтому содержимое за краем барабана «принадлежит» противоположному краю (прокрутка
за край входит с противоположной стороны). Карта при этом рисуется в **одном** экземпляре:
пространство над и под конечной полосой остаётся пустым фоном (прежние три копии-«лента»
выглядели как ошибка отрисовки и были удалены). Материки и границы заранее перекатываются в систему
барабана и только потом обрезаются по ±`CLIP_LAT` (`geoBandClip.cutFeatureCollectionToBand`),
поэтому ничего не пересекает шов закольцовки. Оба слоя делят один аналитический
фит по полосе ±`CLIP_LAT` (размер окна постоянен при любом положении ползунков: барабан
не зумится и не съезжает), и каждый
слой обрезан `clipExtent` по рамке экрана; обрезка ставится
строго после финального `translate` (d3 clipExtent работает в экранных пикселях, но обязан
применяться последним — иначе рассинхронизируется). Закон высоты
зажат до ±`CLAMP_LAT` (чуть дальше края окна), чтобы Меркатор не уходил в бесконечность на
полюсе. Всегда включено `precision(0)`: ряды градуировки барабана обязаны оставаться
линейками — прямыми горизонтальными линиями.
Конические и азимутальные проекции зашивают `gamma` как roll. Для конических проекций берётся пара параллелей `parallels([φ1, φ2])`
(φ1 сохраняет знак `phiOrigin`, при `|phiOrigin| < 10` параллель берётся `±30°`, т.к. у
экватора конус вырожден — совпадает с геометрией вспомогательной поверхности). 2D-карта
дополнительно подгоняется под размер контейнера через `fitProjectionToView` (режим
object-fit: contain), поэтому глобус всегда заполняет доступную область, а диаметр
цилиндра виден через изменение пропорций карты, а не её размера.
Вся геометрия 3D (поверхность, кольцо касания, лучи) выводится из одного модуля
`auxSurfaceGeometry.ts`, поэтому фигуры не могут рассинхронизироваться.

> **Модель Земли:** только **сферическая**. Азимутальное семейство — перспективное:
> проекция определяется положением источника света: центр → гномоническая
> (`geoGnomonic`), антипод → стереографическая (`geoStereographic`),
> бесконечность → ортографическая (`geoOrthographic`). Для конических семейства
> отдельного «источника света» нет — для конуса это вершина конуса, для
> цилиндра лучи идут из центра глобуса на цилиндр.

### Геоданные

Берега материков грузятся из `public/world-110m.topojson` (land, `objects.land`) и
преобразуются из TopoJSON в GeoJSON на лету через `topojson-client`.

### Дизайн-токены

Экспортируются из `src/constants/designTokens.ts` — не хардкодьте hex в компонентах.
Цвета продублированы как CSS-переменные в `src/index.css` (`@theme`), чтобы Tailwind
генерировал утилиты вроде `bg-panel-bg` / `drop-shadow-[…var(--color-neon-blue-soft)]`.

- `BG` — фон приложения: `#05050A`
- `NEON_BLUE` `#00e5ff` — глобус, берега, текст
- `NEON_ORANGE` `#ff6a00` — каркас вспомогательной поверхности
- `NEON_YELLOW` `#ffe600` — источник света, лучи проекции и булавка точки касания
- `NEON_WHITE` `#ffffff` — белые линии аппарата: кольца пересечения поверхности с глобусом и линия разреза (включаются кнопкой «Линии пересечения и линия разреза» одновременно в 3D-сцене и на 2D-карте; по умолчанию выключены)
- `NEON_BLUE_LINE` / `NEON_ORANGE_SOFT` — альфа-варианты неона
- Стеклянные панели: `bg-panel-bg` (CSS-переменная `--color-panel-bg`) + `backdrop-blur` + тонкая рамка

## Тестирование

```bash
npm run test
```

Покрываются: стор и селекторы, маппер проекций, геометрия `auxSurfaceGeometry`, константы,
`ControlPanel`, `ProjectionHeader`, `ProjectionSummary`, `Map2D`, `ErrorBoundary`,
монтирование `App`, а также два «сторожевых» набора — физика геометрии
(`src/__tests__/physics.test.ts`) и соответствие документации коду
(`src/__tests__/docsConsistency.test.ts`). Намеренно **не** тестируются
WebGL/`<Canvas>` и атрибуты `d` SVG-путей (хрупко и зависит от размеров экрана) —
это проверяется только вручную.

При push/PR выполняется CI (`.github/workflows/ci.yml`): `npm ci` → lint → build → test.

## Примечание по окружению разработки (DrvFS)

Если вы работаете в смонтированном Windows-диске (`/mnt/d`, 9P/DrvFS), `npm install`
там падает с `ENOTDIR` при создании `node_modules`, а испорченный dentry не удаляется
изнутри контейнера. В этом окружении зависимости устанавливаются на нативную ФС
(`~/mbp-deps/node_modules`), а `node_modules` в проекте — симлинк на неё
(исходники остаются локальными, `preserveSymlinks` не нужен); `vite.config.ts`
использует `server.watch.usePolling`, так как DrvFS не шлёт `inotify`-события и HMR
иначе не срабатывает. На обычных Linux/macOS/CI это не нужно — достаточно
`npm install` в корне проекта.

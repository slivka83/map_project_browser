### 3.3. Поведение лучей в 3D-сцене

| Проекция | Откуда исходят | Куда падают | Поведение | Что происходит после |
|---|---|---|---|---|
| **Меркатор** | Из центра Земли (внутри глобуса) | На внутреннюю стенку цилиндра | Радиально расходятся во все стороны. Каждый луч проходит через точку на поверхности глобуса | Луч пересекает цилиндр — эта точка становится пикселем на 2D-карте. **Без преломления.** |
| **Поперечный Меркатор** | То же | На внутреннюю стенку горизонтального цилиндра | То же | Цилиндр разворачивается, давая узкую вертикальную полосу на 2D-карте |
| **Наклонный Меркатор** | То же | На стенку наклонного цилиндра | То же | Цилиндр разворачивается под углом |
| **Равнопромежуточная** | Из бесконечности (с востока и запада одновременно) | На стенку вертикального цилиндра | **Параллельные лучи**, горизонтальные, перпендикулярные меридианам | Каждая точка проецируется строго горизонтально. Результат: X=долгота, Y=широта |
| **Галла-Петерса** | Из бесконечности | На стенку цилиндра | **Параллельные лучи под углом ~45°** к оси цилиндра | Угол подобран так, чтобы площади сохранялись. Лучи идут "по диагонали" |
| **Ламберта цилиндрическая равновеликая** | Из бесконечности | На стенку цилиндра | **Параллельные лучи** горизонтально | Как Plate Carrée, но Y = sin(широты), а не сама широта |

**Общее правило для цилиндрических:**
```
        💡 (или параллельные лучи)
         \  |  /
          \ | /
    ═══════╪═══════  ← цилиндр
    ║       ●       ║  ← глобус внутри
    ║     / | \     ║  ← лучи из центра/снаружи
    ║    /  |  \    ║
    ═══════════════
           ↓
    Развернуть цилиндр → 2D карта
```

**Особенность Меркатора:** точки у полюсов дают лучи почти параллельные стенке цилиндра → они пересекают её очень далеко → поэтому Меркатор **обрезается** на ~85° широты (иначе карта уйдёт в бесконечность).

### 3.4. Как это работает в интерфейсе

**Пример 1: Пользователь выбрал "Меркатор"**
- Сегментированный контрол ориентации автоматически переключается на "Ровный" и становится серым (read-only)
- Слайдер стандартной параллели замирает на 0° (экватор) с подписью "Цилиндр касается по экватору"
- В 3D-сцене цилиндр встаёт вертикально, внутри него — глобус, из центра Земли расходятся лучи к цилиндру
- Слайдер центрального меридиана активен: двигая его, пользователь вращает глобус внутри цилиндра (на 2D-карте карта сдвигается по горизонтали)

**Пример 2: Пользователь выбрал "Поперечный Меркатор" (как UTM)**
- Ориентация блокируется на "Поперёк" — цилиндр лежит горизонтально
- Появляется активный слайдер стандартной параллели, но теперь это **меридиан касания**, а не параллель (подпись меняется на "Линия касания цилиндра")
- В 3D видно, что цилиндр касается глобуса по вертикальной линии
- При движении слайдера центрального меридиана — 2D-карта показывает узкую полосу вокруг этой линии

**Пример 3: Пользователь выбрал "Миллера"**
- Контрол источника света становится "🔗 Недоступен" с tooltip
- Вместо него появляется маленькая иконка ⚙️ с подсказкой: "Это формула, а не оптическая проекция. Лучей нет"
- В 3D-сцене цилиндра и лучей нет — только глобус с наложенной сеткой и индикатором "математическое преобразование"
- Остальные контролы работают как у Меркатора

**Пример 4: Пользователь выбрал "Галла-Петерса"**
- Две стандартные параллели появляются и жёстко блокируются на +45° и -45°
- Подпись: "Эта проекция честно показывает площади: Африка здесь в 14 раз больше Гренландии, как и в реальности"
- Лучи в 3D — параллельные (как солнечный свет)

### 4.3. Поведение в 3D-сцене (лучей нет)

**Ни в одной конической проекции из списка нет оптической модели.** Вместо лучей в 3D показывается:

```
         /\
        /  \   ← сам конус
       /____\
      / ( )  \  ← глобус внутри
     /________\
```

**При движении слайдеров параллелей:**
- Конус **физически меняет форму** в 3D-сцене
- Становится острее или шире
- Касается глобуса на новых широтах (видно как две светящиеся окружности)
- При одном касании — конус острее, касается на одной параллели
- При двух — шире, касается на двух параллелях

**Развёртка конуса:** после проецирования конус разрезается вдоль центрального меридиана и разворачивается в сектор круга → 2D-карта.

### 4.4. Особенности работы

**Конические проекции — это всегда математические формулы, а не оптические!**
- В 3D-сцене нет лучей. Вместо них — сам конус, который надевается на глобус
- При движении слайдеров параллелей конус в 3D **физически меняет форму**: становится острее или шире, чтобы коснуться глобуса на новых широтах
- Подпись контрола меняется: "Конус касается глобуса на широте 55°" → "на широте 62°"

**Пример: Ламберта конформная (EPSG:2154 — Франция)**
- Две параллели жёстко связаны математикой конформности (углы сохраняются)
- Пользователь двигает слайдеры параллелей (например, 49° и 44° для Франции)
- В 3D конус подстраивается, касаясь глобуса на этих широтах
- Зона между параллелями подсвечивается зелёным (минимум искажений)
- Выше и ниже — красная зона (искажения нарастают)

**Поликоническая — особый случай:**
- Контролы параллелей становятся "🔗 Недоступен" с tooltip
- В 3D-сцене вместо одного конуса — стопка конусов разного раскрытия, каждый касается на своей широте
- Появляется индикатор: "Поликоническая: для каждой параллели — свой конус"
- Это используется для длинных стран (Россия, Чили)

### 5.4. Детали работы

**Точка касания — главный контрол для азимутальных**
- Всегда активен, представлен двумя способами:
  1. **Пресеты:** Северный полюс / Южный полюс / Экватор / Москва / Свой выбор (клик на мини-глобусе)
  2. **Координаты:** Поля ввода широты/долготы (для продвинутых)

**Гномоническая проекция:**
- Источник света = центр Земли (заблокировано)
- В 3D видно: лучи выходят из центра глобуса и расходятся веером к плоскости
- Особенность: проецируется **только меньше полушария** (точки за горизонтом недостижимы)
- В 2D-карте: при попытке показать область больше полушария — она просто обрезается
- Полезная фишка: если провести прямую линию на 2D-карте между двумя точками — это будет кратчайший путь (дуга большого круга). Интерфейс может предложить инструмент "проложить маршрут"

**Стереографическая:**
- Источник = точка, противоположная точке касания
- Например, если касание на Северном полюсе — свет с Южного полюса
- В 3D видно: лучи проходят сквозь глобус и выходят к плоскости
- Проецирует **всю сферу** (кроме точки, где находится источник)
- Используется для полярных карт (EPSG:3031, 3413)

**Ортографическая:**
- Параллельные лучи из бесконечности
- В 3D: лучи идут ровным строем, как солнечный свет
- Видно **только одно полушарие** (как фотография из космоса)
- При движении точки касания — глобус в 3D вращается, и видно, как меняется "фотография"

**Внешняя перспектива (вид со спутника):**
- Появляется **уникальный контрол**: расстояние до источника света (в радиусах Земли)
- Слайдер от 1.1 (очень близко) до 10 (далеко) радиусов
- При 1.1: видно очень мало территории, сильные искажения
- При 3-5: типичный вид со спутника (как снимки Земли из космоса)
- При >5: приближается к ортографической
- В 3D: источник света — это маленькая иконка спутника 🛰️, которую можно двигать слайдером

**Ламберта азимутальная равновеликая:**
- Нет источника света (чистая математика)
- В 3D: только глобус, плоскость и индикатор "математическая формула"
- Сохраняет площади: Гренландия и Африка показываются в правильном соотношении
- EPSG:3035 используется для карт Европы

**Азимутальная равнопромежуточная:**
- Расстояния **от точки касания** до любой другой точки показаны без искажений
- Используется для карт радиолюбителей (показывает расстояние до станции)
- Может проецировать **всю сферу** — в 3D плоскость бесконечная

## 6. ❌ Где лучей нет совсем (и почему)

| Проекция | Причина отсутствия лучей |
|---|---|
| **Миллера** | Модификация Меркатора с изменённой формулой. Геометрически не выводится |
| **Все конические** (Ламберта, Альберса, равнопромежуточная, поликоническая) | Чисто математические формулы. Можно было бы придумать "коническую перспективную" с точкой света на оси, но это редкая экзотика |
| **Ламберта азимутальная равновеликая** | Формула сохраняет площади, но не является оптической проекцией |
| **Азимутальная равнопромежуточная** | Сохраняет расстояния от центра по формуле, без оптической модели |

## 7. 🔧 БЛОК EPSG

Вместо ESPG проекци должны быть доступны все приведенные выше.  

Когда пользователь выбирает проекцию, приложение:

**1. Парсит определение проекции**
```
EPSG:3857 → Web Mercator (цилиндрическая, Меркатор, источник=центр, параллель=0°)
EPSG:2154 → Lambert-93 France (коническая Ламберта, параллели=49° и 44°, центр=46.5°)
EPSG:3031 → Antarctic Polar Stereographic (азимутальная стереографическая, касание=-90°)
```

**2. Заполняет контролы автоматически**
- **Тип проекции** переключается на нужный (Цилиндр/Конус/Азимут)
- **Вариант проекции** устанавливается в соответствующий (Меркатор/Ламберта/Стереографическая)
- Все параметры (параллели, центральный меридиан, точка касания) подставляются
- Некоторые контролы блокируются (согласно матрице выше)

## 9. 🎯 UX-ПРИНЦИПЫ

### 9.1. Ключевые правила

1. **Никакой геодезической терминологии** в основных контролах — только метафоры (обернуть, надеть, куда светить)
2. **Связь контрол ↔ 3D ↔ 2D**: любое движение слайдера мгновенно видно на всех трёх частях экрана
3. **Визуальные превью вместо цифр**: везде, где можно, показывать картинку, а не число

### 9.2. Стабильный UI

Контролы не прыгают. Вместо скрытия — серое поле "🔗 Недоступен" с hover-подсказкой. Пользователь видит **все возможные параметры**, даже если они сейчас неактивны. Это образовательный момент: "ага, а есть ещё вот такой параметр, просто для этой проекции он не нужен".

### 9.3. Блокировка = объяснение

Когда контрол заблокирован, он не просто серый — рядом появляется подпись:
```
🔒 Стандартная параллель: 0°
   Эта проекция всегда касается экватора
```

### 9.5. Лучи — там, где есть оптическая модель

В 3D-сцене лучи рисуются **только** для проекций с геометрической интерпретацией. Для математических проекций вместо лучей показывается:
- Сам цилиндр/конус/плоскость с сеткой координат
- Подпись: «Математическая формула, без лучей»
- Анимация "переноса" точек: точки на глобусе плавно "перетекают" на поверхность по математическому закону (без визуальных лучей)

### 9.6. EPSG — с объяснением

Для каждой проекции в UI показывается:
- ✅ Есть EPSG: `[код] — [название] — [где применяется]`
- ⚠️ Нет EPSG: «Декоративная/математическая проекция. Не используется в геодезии. Можно выбрать похожую из списка или использовать встроенную формулу»

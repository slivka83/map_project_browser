### Техническое задание (ТЗ): Детализация физических параметров и источников света

**Цель:** Создать замкнутую экосистему, в которой изменение любого из трех элементов (UI-панель параметров, 3D-сцена, 2D-карта) мгновенно и визуально понятно отражается на двух других. Джуниор-разработчик должен реализовать строгий маппинг стейта и визуальных маркеров.

---

#### 1. Архитектура состояния (State Management)

Для обеспечения реактивности использовать глобальный стейт (например, Zustand или Redux Toolkit). Стейт является единственным источником истины.

**Схема стейта (`projectionState`):**

```javascript
{
  globe: { radius: 100 }, // Базовый радиус глобуса (R)
  lightSource: {
    type: 'point', // 'point' | 'linear'
    position: { x: 0, y: 0, z: 0 }, // Влияет на тип (гномоническая, стереографическая и т.д.)
    intensity: 1,
    isInfinite: false // Переключатель в ортографическую проекцию
  },
  surface: {
    type: 'cylinder', // 'cylinder' | 'cone' | 'plane'
    position: { x: 0, y: 0, z: 0 },
    rotation: { x: 0, y: 0, z: 0 }, // Для косых и поперечных проекций
    // Специфичные параметры для цилиндра
    cylinder: { radius: 100, height: 400 },
    // Специфичные параметры для конуса
    cone: { radius: 100, height: 200, apexY: 150 },
    // Специфичные параметры для плоскости
    plane: { distance: 100 }
  },
  // Вычисляемые параметры для d3-geo (обновляются автоматически)
  d3Config: {
    parallels: [], // Стандартные параллели
    rotate: [0, 0, 0], // Центральный меридиан и смещение
    scale: 150
  }
}

```

#### 2. Реализация принципа «Абсолютной связи» (UI ↔ 3D ↔ 2D)

Разработчик обязан реализовать цветовую и событийную синхронизацию (Сквозная подсветка).

* **Цветовое кодирование:**
* Линии пересечения поверхности с глобусом (стандартные параллели) всегда выделяются **ярко-красным** цветом во всех трех средах.
* Центральный меридиан выделяется **синим** цветом.
* Точка источника света и проецирующие лучи выделяются **желтым** цветом.


* **Синхронизация при наведении (Hover Effect):**
* Если пользователь наводит курсор на инпут `[Параллель 1: 30°]` в UI-панели, эта линия должна начать пульсировать (менять `opacity` или `emissive` материал) одновременно на 3D-глобусе (как кольцо пересечения) и на 2D-карте (как линия сетки).


* **Визуализация лучей (Raycasting Visualization):**
* В 3D-сцене необходимо отрисовать 12-24 пунктирных линий (`THREE.LineBasicMaterial` с `dashed: true`), исходящих из источника света, проходящих сквозь узлы координатной сетки глобуса и упирающихся в поверхность цилиндра/конуса/плоскости.
* При движении источника света эти лучи должны в реальном времени перестраиваться.

#### 3. Детализация 3D-объектов и их математика (Three.js)

Разработчик должен использовать `THREE.TransformControls` для всех интерактивных элементов.

##### 3.1. Точечный источник света (`THREE.PointLight` + `THREE.Mesh` сферы)

* **Взаимодействие:** Пользователь тянет за оси (X, Y, Z).
* **Ограничения (Constraints):** Реализовать функцию «прилипания» (snapping) в координатах:
* $(0, 0, 0)$ — подсветить в UI текст «Гномоническая проекция (от центра)».
* На поверхности глобуса $(0, \pm R, 0)$ — подсветить «Стереографическая проекция».


* **Бесконечность:** Кнопка в UI «Удалить в бесконечность». В 3D источник света улетает по вектору своего текущего смещения на расстояние `R * 1000`, лучи становятся параллельными (`THREE.DirectionalLight`). Подсветить текст «Ортографическая проекция».

##### 3.2. Цилиндр (`THREE.CylinderGeometry`)

* **Взаимодействие:** На поверхности цилиндра разместить ползунок (контрол масштабирования) для изменения радиуса (`cylinder.radius`).
* **Математика пересечений (ОБЯЗАТЕЛЬНО для маппинга в D3):**
* Если радиус цилиндра $r$ равен радиусу глобуса $R$ ($r = R$), образуется одна стандартная параллель (экватор 0°, если нет вращения).
* Если цилиндр секущий ($r < R$), образуются две стандартные параллели.
* **Формула для разработчика:** Широта стандартных параллелей $\theta = \pm \arccos(r / R)$ (перевести из радиан в градусы для D3).
* *Обработка ошибок:* Если $r < 0$ или $r > R$ (цилиндр не касается глобуса) — лучи не пересекают поверхность, блокировать рендер карты, выводить предупреждение в UI.



##### 3.3. Конус (`THREE.ConeGeometry`)

* **Взаимодействие:** Контрол для изменения угла при вершине (раскрытие конуса) и контрол для перемещения вершины по оси Y.
* **Математика пересечений:**
* Вычислять точки пересечения образующей конуса и сферы.
* Результатом должны быть либо одна точка (касание — одна стандартная параллель), либо две (секущий конус — две стандартные параллели). Передать эти градусы в массив `d3Config.parallels`.



##### 3.4. Плоскость (`THREE.PlaneGeometry`)

* **Взаимодействие:** Движение только по вектору нормали к плоскости (ближе/дальше от глобуса) и вращение вокруг глобуса (`rotation`).
* **Математика:**
* Вращение плоскости `rotation.x` и `rotation.y` должно напрямую передаваться в массив `d3Config.rotate = [lambda, phi, gamma]`. Это позволит пользователю крутить плоскость в 3D и видеть, как на 2D-карте центр проекции смещается в полярную или косую зоны.

#### 4. UI-Панель параметров (Математическая справка)

Разработчик должен создать UI-компонент, который работает в режиме **двусторонней привязки** (two-way binding) со стейтом 3D-сцены.

**Состав панели:**

1. **Блок "Источник света":**
* Координаты [X, Y, Z] (редактируемые инпуты типа `number`).
* Тумблер "Бесконечно удаленный" (чекбокс).


2. **Блок "Вспомогательная поверхность":**
* Выпадающий список (Цилиндр, Конус, Плоскость).
* Инпуты ориентации (Наклон X, Наклон Y). *Изменение этих полей физически крутит объект в 3D.*


3. **Блок "Вычисленные картографические параметры" (Read-only + Edit):**
* `Стандартные параллели:` [ __° ], [ __° ].
* `Центральный меридиан:` [ __° ].
* *Поведение:* При ручном вводе значения (например, пользователь вбил параллель 45°) — 3D-цилиндр должен автоматически изменить свой радиус так, чтобы пересечь глобус ровно на 45-й широте.


4. **Блок "Экспорт":**
* Кнопка «Скопировать D3-конфиг». Генерирует готовый код: `d3.geoAlbers().parallels([30, 45]).rotate([-10, 0, 0])`.

#### 5. Последовательность обработки событий (Event Loop) для разработчика

Чтобы избежать циклических зависимостей, разработчик должен реализовать следующий поток данных:

1. **User Action:** Пользователь тянет 3D-цилиндр за радиус (событие `change` у `TransformControls`).
2. **State Update:** Обновляется `state.surface.cylinder.radius`.
3. **Math Middleware:** Вызывается функция `calculateD3Params(state)`. Она использует формулу $\arccos(r/R)$, получает, например, `[30, -30]` градусов.
4. **State Update:** Обновляется `state.d3Config.parallels`.
5. **Render:**
* React ререндерит UI, показывая новые параллели в инпутах.
* Three.js ререндерит красные кольца-пересечения на глобусе на нужных широтах.
* D3 перерисовывает `path` 2D-карты с новыми искажениями.
* *Оптимизация:* Для D3 использовать `requestAnimationFrame` или `throttle` на 16ms (60 FPS), чтобы карта не тормозила при плавном драг-н-дропе в 3D.

# Архитектурно-кодовый аудит проекта map_project_browser

Я детально изучил репозиторий. Ниже — полный разбор: что работает хорошо, где зарыты грабли, что срочно править, а что я бы сделал иначе. Всё максимально подробно, с указанием конкретных файлов и строк, чтобы джуниор мог взять и исправить, не задавая вопросов.

---

## 1. Общее впечатление

**Что хорошо:**
- Проект собран на современном стеке (Vite 6, React 19, TypeScript 5.8, Zustand, Three.js)
- Есть строгий режим TypeScript, декларировано «без `any` в пропсах»
- Единый источник правды для состояния — Zustand
- Геометрия 3D вынесена в один модуль (`auxSurfaceGeometry.ts`), чтобы поверхности, кольца и лучи не рассинхронизивались
- Есть дизайн-токены, цвета не хардкодятся в компонентах
- Есть CI (GitHub Actions) с lint → build → test
- Есть тесты (Vitest + React Testing Library)

**Что настораживает:**
- Это SPA без бэкенда, но геоданные грузятся из `public/` — это нормально
- Кодовая база компактная, но есть несколько мест, где логика размазана или дублируется

## 2. Архитектура — разбор

### 2.1. Слой состояния (Zustand) — `src/store/useAppStore.ts`

**Что есть:**
- Единый стор с параметрами проекции, флагами (`showTissot`, `showBorders`, `detailedMap`) и геоданными
- Экшены: `setParam`, `setShowTissot`, `setFamily`, `resetParams`, `applyPreset`, `loadGeoData`

**Проблемы:**

1. **Смешение геоданных и параметров UI в одном сторе** — это не критично, но нарушает принцип разделения ответственности. Геоданные — это загруженные ассеты, параметры проекции — состояние приложения, флаги — UI-состояние. Всё в одной куче.

2. **`loadGeoData` загружает 4 разных набора данных** (110m land, 50m land, 50m countries, 110m countries), но не имеет механизма отмены запросов. Если пользователь быстро переключает что-то, могут наложиться старые и новые ответы.

3. **Нет обработки ошибок загрузки** — если `fetch` упал, стор просто остаётся с `null`. Пользователь увидит пустую карту без пояснений.

4. **`applyPreset`** — это `set({ ...preset })`, который **перезаписывает всё**, что пришло в preset. Если в preset нет `showTissot` или `detailedMap`, они остаются как были — это ок. Но если в preset есть только `family`, то `distortion` **не** сбрасывается на дефолтный для этого семейства — это **баг** (потому что `setFamily` так делает, а `applyPreset` — нет).

5. **`setFamily`** вызывает `defaultParamsForFamily(family)`, что сбрасывает `lambda0`, `phiOrigin`, `scaleFactor`, `falseEasting`, `falseNorthing` на дефолты. Это правильно.

6. **Тип `ProjectionParams` дублируется** — он объявлен в сторе, но используется повсюду. Это нормально, но если бы он был вынесен в `src/types/`, было бы чище.

### 2.2. Селекторы — `src/store/selectors.ts`

**Что есть:**
- `useProjectionParams` — мемоизированный селектор через `useShallow`
- `useGeoData` — аналогично

**Хорошо:** Селекторы есть, мемоизация работает.

**Плохо:** Селекторы возвращают **весь объект**, а не отдельные поля. Это значит, что любой компонент, использующий `useProjectionParams`, перерендерится при **любом** изменении любого параметра проекции. Для мелких компонентов (типа одного слайдера) это избыточно. Лучше было бы использовать атомарные селекторы.

### 2.3. Маппинг проекций — `src/utils/projectionMapper.ts`

**Что есть:**
- `getD3Projection` — фабрика D3-проекций по `(family, distortion)`
- `fitProjectionToView` — подгонка проекции под размер контейнера
- `computeAreaDistortion` — вычисление искажений площади

**Проблемы:**

1. **`fitProjectionToView` не экспортируется из этого файла?** В импортах он есть, но я не вижу его определения в просмотренном фрагменте (файл обрезан). Если он определён в этом же файле ниже — ок. Если нет — это ошибка.

2. **`localAreaScale` использует `quadSelfIntersects`** — этой функции **нет** в просмотренном коде. Возможно, она определена ниже (файл обрезан на 103 строках). Если нет — это **критическая ошибка**: код не скомпилируется.

3. **Для конических проекций используется `parallels([parallel, parallel])`** — это корректно для касательного конуса. Но в комментарии сказано «near the equator a cone is degenerate, fall back to STD_PARALLEL_FALLBACK» — это правильно и согласовано с `auxSurfaceGeometry.ts`.

4. **Вращение использует отрицательные знаки** — `.rotate([-lambda0, -phiOrigin])` — это стандартное поведение D3, всё верно.

### 2.4. Геометрия 3D — `src/utils/auxSurfaceGeometry.ts`

**Что есть:**
- `lonLatToVec3` — перевод (lon, lat) в 3D-координаты
- `computeTangentBasis` — базис в точке касания
- `computeAuxSurfaceParams` — параметры вспомогательной поверхности (цилиндр/конус/плоскость)
- `computeAuxGraticule` — сетка meridians/parallels для поверхности
- `computeTangencyRing`, `computeAuxSphereIntersections`, `computeCentralMeridianRays`

**Хорошо:** Единый источник геометрии — действительно, все 3D-фигуры строятся из одного модуля. Это **сильная сторона** проекта.

**Проблемы:**

1. **`worldPerPixel`** — функция, которая переводит пиксели в мировые единицы. Используется для синхронизации 2D и 3D. Это **правильный подход**, но я бы вынес это в `constants/geometry.ts`, а не держал внутри утилиты.

2. **Магия чисел:** `AUX_LENGTH = 2.6`, `CONE_Y_BASE = 0.35`, `RING_RADIUS = 0.45` — все вынесены в константы, **молодцы**. Но я бы добавил комментарии, **почему** именно такие значения (подобраны визуально? вычислены?).

3. **`computeCone`** использует `standardParallelDeg` — это общая функция из `geometry.ts`, всё согласовано.

### 2.5. Компоненты

#### 2.5.1. `App.tsx`

```tsx
useEffect(() => { void loadGeoData(); }, [loadGeoData]);
```


**Проблемы:**
- `void` — это подавление предупреждения о необработанном промисe. Лучше использовать `.catch()` или `try/catch` внутри.
- Нет индикатора загрузки — пользователь видит пустой экран, пока грузятся данные.
- Нет обработки ошибок загрузки.

#### 2.5.2. `ControlPanel.tsx`

**Что есть:**
- Табы для выбора семейства проекций
- Слайдеры для `lambda0`, `phiOrigin`, `scaleFactor`
- Дропдаун для выбора искажения
- Кнопки EPSG и сброса

**Проблемы:**

1. **Слайдеры не имеют меток `min`/`max` в UI** — пользователь не знает диапазон, пока не начнёт двигать. Диапазоны есть в коде, но их стоило бы отобразить.

2. **`scaleFactor`** — слайдер без суффикса (`suffix=""`), в отличие от других. Это ок, но сбивает с толку.

3. **Отсутствует `showTissot` и `showBorders` в панели** — они есть в сторе, но в ControlPanel их нет. Они управляются из `Map2D` через иконки. Это **размазывает UI-логику** по разным компонентам — не смертельно, но не идеально.

4. **`DistortionSelect`** — это обёртка над `Dropdown`. Почему бы не использовать `Dropdown` напрямую?

#### 2.5.3. `Map2D.tsx`

**Что есть:**
- Адаптивная SVG-карта с подгонкой под размер контейнера
- Гратула, берега, индикатрисы Тиссо
- Кнопки включения Tissot, границ и детализации

**Проблемы:**

1. **`useElementSize`** — кастомный хук для отслеживания размера контейнера. Реализация через `ResizeObserver` — хорошая. Но он **завязан на `clientWidth`/`clientHeight`**, что может давать 0 при скрытых элементах.

2. **`pathGenerator`** пересоздаётся при каждом изменении **любого** параметра проекции или размера. Это правильно, но может быть дорого. Можно было бы мемоизировать проекцию отдельно от пути.

3. **`computeAreaDistortion`** вызывается, но я не вижу, где результат отображается. В тестах упоминается «area-distortion label in the bottom-right corner», но в коде `Map2D` я этого не вижу (файл обрезан).

4. **Логика выбора данных** — `baseLand = detailedMap ? (land50GeoJson ?? geoJsonData) : geoJsonData` — это **правильный fallback**, если 50m не загрузились.

#### 2.5.4. `GlobeScene.tsx`

```tsx
export default function GlobeScene() {
  const params = useProjectionParams();
  const geoJson = useAppStore((s) => s.geoJsonData);
  return ( <Canvas> ... </Canvas> );
}
```


**Проблемы:**
- Компонент **всегда рендерит Canvas**, даже если `geoJson === null`. Это ок, но можно было бы показать заглушку «Loading...».
- `OrbitControls` включены — это хорошо для интерактивности.

#### 2.5.5. `Globe.tsx`

**Что есть:**
- Прозрачный глобус с неоновыми линиями
- `Graticule` — меридианы и параллели
- `Coastlines` — береговая линия из GeoJSON

**Проблемы:**

1. **`Graticule`** использует шаг 30° для меридианов и 3° для точек — это даёт ~120 точек на меридиан, что **много** для 3D. Можно было бы использовать 5° или 10°.

2. **`Coastlines`** — для каждого кольца создаётся отдельный `Line`-компонент. Это может быть **очень много** для детальной карты (сотни полигонов). Лучше объединять все линии в один `LineSegments` или использовать `instanced mesh`.

3. **`GLOBE_INFLATE = 1.002`** — линии поднимаются над поверхностью сферы, чтобы не было z-fighting. **Правильное решение**.

#### 2.5.6. `AuxSurface.tsx`

**Что есть:**
- Вспомогательная поверхность (цилиндр/конус/плоскость)
- Использует `computeAuxGraticule` для построения сетки

**Проблемы:**

1. **Для плоскости используется `quatFromNormal`** — это поворот сетки по нормали. **Хорошо**, что геометрия поворачивается, а не группа.

2. **Для конуса и цилиндра** — просто рендерятся линии. Всё ок.

3. **`AuxSurface`** рендерится всегда, даже если `scaleFactor` делает поверхность невидимой (например, 0). Можно было бы добавить проверку.

#### 2.5.7. `IntersectionDisks.tsx`

**Что есть:**
- Кольца пересечения поверхности с глобусом
- Использует `computeAuxSphereIntersections`

**Хорошо:** Если пересечений нет — ничего не рендерится. **Правильно**.

#### 2.5.8. `Rays.tsx`

**Что есть:**
- Веер лучей от центра глобуса к поверхности
- `depthTest: false` — лучи видны сквозь глобус

**Хорошо:** `depthTest: false` — **правильное решение** для лучей, которые должны быть видны внутри сферы.

#### 2.5.9. `Dropdown.tsx`

**Что есть:**
- Кастомный дропдаун с тёмной темой
- Generic `T` для типа значения

**Проблемы:**

1. **`allLabel`** — когда передан, добавляется опция с `value: '' as T`. Это **опасный каст** — `'' as T` может не соответствовать реальному типу `T`. Лучше было бы сделать `value: undefined` или `null`.

2. **`initialOpen`** — есть, но не используется в `ControlPanel` (там всегда `false`).

3. **Закрытие по клику вне** — работает через `document.addEventListener`. Это ок, но можно было бы использовать `useOnClickOutside` из библиотеки.

#### 2.5.10. `EpsgCatalog.tsx`

**Что есть:**
- Модальное окно через `createPortal`
- Фильтры по коду, названию, типу, искажению, единицам

**Проблемы:**

1. **Фильтры используют `useState` для каждого поля** — это 5 разных стейтов. Можно было бы объединить в один объект.

2. **`familyOptions` и `distortionOptions`** вычисляются через `useMemo` с `Array.from(new Set(...))` — **правильно**, но можно было бы вынести в константу.

3. **`filterValue` и `setFilterValue`** — функции-маршрутизаторы. Работают, но выглядят как костыль. Лучше бы использовать `useReducer` или объект стейта.

## 3. Код-стайл и TypeScript

### 3.1. Хорошее
- Есть дизайн-токены, цвета не хардкодятся
- Tailwind CSS v4 используется
- Есть строгий режим TypeScript

### 3.2. Проблемы

1. **`any` в пропсах** — в README сказано «без `any`», но я вижу в `Dropdown.tsx`:
   ```tsx
   const items: DropdownOption<T>[] = allLabel !== undefined ? [{ value: '' as T, label: allLabel }, ...options] : options;
   ```
    — это **не `any`**, но это **опасный каст**. Тип `T` может быть `number`, а `''` — это строка.

2. **Отсутствие экспортов** — в некоторых файлах я не вижу явных `export` для некоторых функций (например, `fitProjectionToView` в `projectionMapper.ts` — он используется в `Map2D`, но я не вижу его экспорта в просмотренном фрагменте).

3. **Именование** — `geoJsonData`, `land50GeoJson`, `countriesGeoJson`, `countries110GeoJson` — слишком похожи, легко перепутать. Я бы использовал более явные имена: `land110m`, `land50m`, `borders50m`, `borders110m`.

4. **Комментарии** — в коде много комментариев на русском, что **хорошо** для понимания. Но некоторые комментарии устарели или дублируют очевидное.

## 6. Физика и математика

### 6.1. Математика проекций

**Что правильно:**
- Используются стандартные D3-проекции
- Вращение через `.rotate([-lambda0, -phiOrigin])` — стандарт D3
- Для конических проекций используется `parallels([parallel, parallel])` — касательный конус
- Единый `MAP_SCALE = 100` для 2D и 3D

**Что можно улучшить:**
- `standardParallelDeg` с fallback на 30° при `|phiOrigin| < 10` — это **костыль**, но необходимый, потому что конус вырождается у экватора. В комментарии это объяснено.

### 6.2. 3D-геометрия

**Что правильно:**
- `worldPerPixel = radius / MAP_SCALE` — синхронизация 2D и 3D
- `GLOBE_INFLATE = 1.002` — предотвращает z-fighting
- `depthTest: false` для лучей

**Что можно улучшить:**
- **Количество сегментов** — `RING_SEGMENTS = 96` — для колец это много, можно 64. `RAY_COUNT = 20` — для лучей нормально.
- **Производительность 3D** — при детальной карте (50m) количество полигонов может быть большим. Можно добавить LOD (уровни детализации).

## 8. Что критично и требует срочного исправления

### 🔴 Критические ошибки (блокируют работу)

1. **`quadSelfIntersects` не определён** в `projectionMapper.ts` — если эта функция действительно отсутствует, код **не скомпилируется**. **Срочно**: проверить, есть ли она в полной версии файла. Если нет — добавить.

2. **`fitProjectionToView` используется, но не экспортируется** — в `Map2D.tsx` импортируется `fitProjectionToView` из `projectionMapper`, но в просмотренном фрагменте `projectionMapper.ts` я не вижу этого экспорта. **Срочно**: проверить экспорт.

3. **`applyPreset` не сбрасывает `distortion` на дефолтный для семейства** — это **логическая ошибка**. Пользователь применяет пресет с `family: 'azimuthal'`, но `distortion` остаётся `'conformal'` (от предыдущего состояния), хотя для азимутальных дефолт — `'equalArea'`. **Исправить**:
   ```ts
   applyPreset: (preset: Partial<ProjectionParams>) => set((s) => {
     const newFamily = preset.family ?? s.family;
     const defaultDist = DEFAULT_DISTORTION[newFamily];
     return {
       ...s,
       ...preset,
       distortion: preset.distortion ?? defaultDist,
     };
   }),
   ```

### 🟠 Высокий приоритет

4. **Нет обработки ошибок загрузки геоданных** — пользователь видит пустой экран без объяснения. **Добавить**:
   - Стейт `loading` и `error` в стор
   - Индикатор загрузки в `App`
   - Сообщение об ошибке с кнопкой «Повторить»

5. **Отсутствует индикатор загрузки** — пока грузятся данные (может быть 1-2 секунды), интерфейс пустой. **Добавить** спиннер или скелетон.

6. **`loadGeoData` без отмены запросов** — если пользователь быстро переключает что-то, запросы могут накладываться. **Добавить** `AbortController` или использовать `swr`/`tanstack-query`.

### 🟡 Средний приоритет

7. **Производительность 3D** — для детальной карты (50m) количество полигонов может быть большим. **Оптимизировать**: использовать `LineSegments` вместо множества `Line`.

8. **Смешение ответственности в сторе** — выделить геоданные в отдельный срез или использовать отдельный стор для ассетов.

9. **Нет адаптивной вёрстки** — на мобильных экранах приложение не работает. **Добавить** медиа-запросы или использовать Grid с колонками, которые схлопываются.

## 10. Что я бы убрал

1. **`detailedMap` флаг** — зачем пользователю переключать детализацию? Лучше всегда показывать максимальную детализацию, а производительность оптимизировать через LOD.

# AGENTS.md

## Project status
Working MVP of «Carto-Space» — an interactive cartographic-projection simulator (educational tool showing the 3D Earth ↔ 2D map relationship). Client-side SPA only: **no backend, no external APIs**; all projection math runs in-browser. Product/legacy specs live in `docs/BRD.md` (business, Russian). The historical `docs/new_spec` / `docs/specification.md` files were never created — **this `AGENTS.md` is the authoritative implementation reference.** The app UI language must be Russian.

## Commands
Run **directly from the project directory** `/mnt/d/_projects/pet_project/map_project_browser`:
- `npm run dev` — Vite dev server
- `npm run build` — `tsc -b && vite build` (typecheck + production build)
- `npm run lint` — ESLint
- `npm run test` — Vitest (`vitest run`); `npm run test:watch` for watch mode
- `npm run test:coverage` — Vitest with V8 coverage report (writes to `coverage/`, git-ignored); local-only, no CI thresholds / no Codecov upload. The 3D scene / viz-renderer components and pure style/token modules are excluded (per §9.3 they're intentionally untested), so the report reflects only the actually-exercised code.
- `npm run preview` — preview the built app

Typecheck is part of `build` (`tsc -b`); there is no separate `typecheck` script. `lint` runs before `build` in CI, so lint errors fail the build there.

## Dev workspace / DrvFS workaround (CRITICAL)
`/mnt/d` is a Windows-mounted drive (9P/DrvFS). `npm install` fails there with `ENOTDIR` on `mkdir node_modules`, and a corrupted `node_modules` dentry cannot be removed from inside the container. We keep a real `node_modules` on the **native Linux filesystem** and symlink it into the project:
- Native home for deps lives on the **persistent** WSL filesystem (NOT `/tmp`, which is wiped on every reboot): `~/mbp-deps/node_modules`, created via `npm ci` inside `~/mbp-deps` (that dir also holds `package.json` + `package-lock.json`). Use the WSL home of whichever user runs the build — typically `/home/<user>/mbp-deps`.
- In the project dir, `node_modules` is a symlink → `~/mbp-deps/node_modules` (the symlink itself lives on the Windows disk under `/mnt/d`, so it survives reboots too). `eslint.config.js` is a real native copy (or symlink). No other source/config symlinks are needed.
- `vite.config.ts` sets `server.watch.usePolling` because DrvFS emits no `inotify` events, so Vite's watcher otherwise never sees edits under `/mnt/d` (HMR won't fire). No `preserveSymlinks` is needed — sources are local.

Because the native deps and the project symlink are both persistent, **no setup is needed after a reboot** — just `npm run dev` from WSL. The one-time setup (run once from WSL): `H=~/mbp-deps; mkdir -p "$H" && cp package.json package-lock.json "$H"/ && cd "$H" && npm ci`, then `ln -sfn "$H/node_modules" /mnt/d/_projects/pet_project/map_project_browser/node_modules`. Only re-run this if the symlink/target is ever deleted. **Do NOT run `npm install`/`npm ci` inside `/mnt/d`.**

## Architecture (how it is wired)
- Four projection families (the old single `azimuthal` family was split into two): `cylindrical`, `conic`, `azimuthalPerspective`, `azimuthalMath`. Cylindrical/conic have developable aux surfaces (cylinder/cone) shown in 3D; `azimuthalPerspective` uses a tangent projection plane (the light-source perspective family); `azimuthalMath` uses a plane with the analytic (no-light) `distortion` mapping (no rays).
- **14 named variants** across the four families:
  - `cylindrical`: `equirectangular`, `mercator`, `transverseMercator`, `obliqueMercator`
  - `conic`: `lambertConformal`, `albers`, `equidistantConic`
  - `azimuthalPerspective`: `gnomonic`, `stereographic`, `orthographic`, `verticalPerspective`, `tiltedPerspective`
  - `azimuthalMath`: `lambertAzimuthalEqualArea`, `azimuthalEquidistant`
  - The legacy variants `miller`, `gallPeters`, `lambertCylEqualArea`, `polyconic` were **removed**.
- Single Zustand store `src/store/useAppStore.ts` is the **only** source of truth; UI / 2D / 3D components only read from it or call its actions (`setParam`, `setVariant`, `setShowTissot`, `setFamily`, `resetParams`, `applyPreset`, `loadGeoData`, and the many `setX` helpers). `setFamily(family)` switches the family **and resets to the family-default variant** (cylindrical → `mercator`, conic → `lambertConformal`, azimuthalPerspective → `gnomonic`, azimuthalMath → `lambertAzimuthalEqualArea`), which in turn sets the appropriate `distortion`, `azLight`, and locked param values. `setVariant(variant)` switches the named projection variant within the current family, setting `family`, `distortion`, `azLight`, and default params accordingly. `resetParams()` resets all params to the current family/variant defaults.
- `src/utils/projectionMapper.ts` exports `getD3Projection(state)`, `computeAreaDistortion(params)`, `fitProjectionToView(proj, w, h, margin)`, `isPointerOverGlobe(path, x, y)`, `makeVerticalPerspective(heightKm)` (and the intended tilted-perspective capability via `makeTiltedPerspective` / `makeVerticalPerspective`), the `FIT_SPHERE` constant, the local-area helpers `localAreaScale(proj, lon, lat, d)` (px² per steradian at a point, or null off-projection / on a discontinuity), `referenceAreaScale(params)` (least-distorted area scale — the heatmap baseline), `cellAreaDistortion(proj, reference, lon, lat, d)` (per-cell excess percentage), and `makeCircleFitSphere(lambda0, phiOrigin, capDeg)` (a spherical-cap fit target for the azimuthal-math family, sized by `circleRadiusKm`). It maps (variant × `family` × `distortion`) → a D3 projection, then applies `proj.rotate([-(lambda0), -phiOrigin, rotZ]).scale(MAP_SCALE * scaleFactor).translate([VIEW_CENTER_X + falseEasting, VIEW_CENTER_Y + falseNorthing])` (constants from `constants/geometry.ts`; `MAP_SCALE=100`, `VIEW_CENTER_X=400`, `VIEW_CENTER_Y=300`). Note the **negative** rotation signs. `makeVerticalPerspective(heightKm)` builds a satellite-perspective (vertical) azimuthal projection from a height in km. The `variant` field selects the named projection. For the **cylindrical** family `gamma` is **ignored** in the 2D rotation (`rotate([-(lambda0), -phiOrigin, 0])`) — the 2D map is the unrolling of the cylinder in its OWN frame, so it is invariant under the cylinder's tilt in space; the 3D rays are bound to the tube and rotate with it, so the map still shows exactly what the rays project onto the tube. The 2D map's **FRAME stays a straight rectangle** (straight surface parallels, guaranteed by `precision(0)`). Conic / azimuthal keep the true `gamma` roll (their orientation genuinely changes in space), so `rotZ = -gamma` there. For the **cylindrical** family the diameter (`scaleFactor`) is the cylinder radius R·`scaleFactor`; the cylinder meets the globe at the contact parallels ±arccos(`scaleFactor`). Latitudes beyond ±`CLIP_LAT` (from the cylinder axis, in the local frame) are clamped so the tube is **finite**. The cylindrical projection is built with `precision(0)` (adaptive resampling OFF) so the parallels stay straight horizontal lines rather than bending into an "egg". `fitProjectionToView` overrides scale/translate to fit the 2D map to its container (the fixed `scale(100)` is only used by the 3D ray math). It fits a **clipped ±85° sphere** (`FIT_SPHERE`) to the viewport, NOT a full `{type:'Sphere'}` (the pole maps to infinity for some projections, collapsing the scale). The azimuthal light-source mapping: `center` → `geoGnomonic`, `antipode` → `geoStereographic`, `infinity` → `geoOrthographic`; the `azimuthalMath` family uses the analytic `distortion` mapping (equal-area / equidistant, no light). `verticalPerspective` / `tiltedPerspective` use `makeVerticalPerspective(heightKm)` / `makeTiltedPerspective(heightKm, tiltDeg, azimuthDeg)` (height from `azHeight`; tilt/azimuth from `azTiltDeg` / `azAzimuthDeg`).
- 2D `src/components/Map2D.tsx`: responsive SVG (measures its container via `ResizeObserver`) whose projection is fitted with `fitProjectionToView`; graticule, coastlines from `land50GeoJson` (≥50m detail), optional country-border layer from `countriesGeoJson`, and optional Tissot indicatrices via `d3Geo.geoCircle().radius(5)` on a 30° grid. The globe always fills the viewport (with a small uniform margin) for every `scaleFactor`, fitted to the container preserving the projection's own aspect ratio (`object-fit: contain`). The cylinder diameter (cylindrical) is therefore NOT visible as a 2D size change — it shows through the map's aspect and through the 3D / Tissot intersection rings and the `Искажение площади` number. The **Индикатрисы Тиссо**, **Детализация карты** and **Границы стран** buttons are always visible together as a single horizontal row in the map's top-right corner. When detail is off, `Map2D` draws the lightweight 110m `geoJsonData` land with 110m borders (`countries110GeoJson`) instead of the 50m datasets. The map's **bottom-right corner** shows a small glass label `Искажение площади: NN%` — the area-weighted area distortion, computed by `computeAreaDistortion` (in `projectionMapper.ts`): it samples local area-scale factors on a fine lon/lat grid and reports the mean relative area excess (equal-area projections → ~0%). The 100% reference is the area scale **at the standard parallel (where true scale = 1)**. The map's **bottom-left corner** carries a neon link to the Stepik course «Геопространственный анализ данных на Python» (https://stepik.org/a/258792).
- 3D scene `src/components/GlobeScene.tsx` composes the thin components (all flat under `components/`, no `Scene3D/` subfolder): `Globe.tsx` (transparent dark sphere with neon-blue **3D-line** coastlines + graticule — NOT the `CanvasTexture`/orthographic variant from the old spec), `AuxSurface.tsx` (fully transparent neon-orange **wireframe** of the developable surface — its own meridians + parallels; cylinder for cylindrical, cone for conic, plane for azimuthal/perspective), `IntersectionDisks.tsx` (hollow neon-green rings marking the **actual** intersection of the aux surface with the globe — 0, 1 or 2 circles; the component renders nothing when the surface does not touch the globe), `LightSource.tsx`, `Rays.tsx`, and the visualization-method renderers (`VizMethodRenderer.tsx` dispatches to `PerpendicularNormals.tsx`, `ParticleTransfer.tsx`, `MagneticField.tsx`, `PeelOff.tsx`, `WaveProjection.tsx`, `LaserScanner.tsx`, `GeometricConstruction.tsx`, `ShadowPlay.tsx`), plus `CutLine.tsx`, `TouchPointPin.tsx`, and `CircularSlider.tsx` / `Toggle.tsx` UI helpers. (The satellite/observer marker for the perspective azimuthal variants is rendered inline inside `LightSource.tsx`.) `GlobeScene` computes the developable-surface geometry once (`computeAuxSurfaceParams`, memoized on the projection params) and passes the resulting `surface` object down so all consumers share one computation and can never drift apart. The azimuthal aux-plane wireframe rotates its grid points directly by the tangent-basis quaternion so its orientation is always correct. `GlobeScene` adds `OrbitControls` (from `@react-three/drei`, `makeDefault`, pan disabled) so the user can rotate/zoom the camera. The 2D map (`Map2D.tsx`) and the 3D globe share a **hover linkage**: hovering either view reads the (lon, lat) under the cursor into the store's `hoverLonLat` and the other view draws a matching yellow marker. Hovering the **2D map** (with `showHoverRay` on) draws the cursor projection ray via `projectToAuxWorld`. Hovering the **3D globe** does **not** draw the ray or the marker (the hover highlight is driven solely by the 2D map).
- `src/utils/auxSurfaceGeometry.ts` is the **single source of truth** for all 3D geometry: `computeAuxSurfaceParams`, `computeAuxGraticule`, `computeAuxSphereIntersections` (the real aux-surface↔globe intersection circles, in 3D world coords) and `computeAuxSphereIntersectionsLonLat` (the same circles projected back to lon/lat for the 2D map's `showIntersection` layer), `auxPointToWorld` (the single world-transform for the aux surface, shared by `AuxSurface` and the rays so they can never drift), `computeCentralMeridianRays` (the central-meridian ray fan) and `projectToAuxWorld` (the per-point ray used by the hover demo), `computeTangentBasis`, `lonLatToVec3` (`RADIUS = 10`) and its inverse `vec3ToLonLat` (used by `GlobeScene` to read the cursor's lon/lat off the 3D globe for the hover linkage). Surface, ring, and rays derive from the same math so they can never drift apart. (Replaces the old `rayGeometry.ts`.) It also exposes the new visualization-method math: `computeSatellitePosition`, `computeOrbitalPath`, `computeCutLine`, `computePerpendicularNormals`, `computeParticleTrajectories`, `computeMagneticFieldLines`, `computeLaserScanRing`, and the vector helpers `vec3Distance`, `vec3Normalize`. `computeCone(phi1, phi2, radius, scaleFactor)` supports both **tangent** (φ1 = φ2) and **secant** (φ1 ≠ φ2, same hemisphere) cones; the cone sits in the **signed** hemisphere of `phiOrigin` (so a southern `phiOrigin` yields a south-pointing cone) while the parallel *magnitude* uses the equatorial `30°` fallback on `|phiOrigin|`. `gamma` (stored in **degrees** in the store) tilts the cylinder/cone/plane for oblique & transverse aspects — it is converted to radians inside this module and inside `AuxSurface.tsx` (Three.js rotations are radians), so the rays and the wireframe stay aligned. `computeCentralMeridianRays` honours the azimuthal `azLight` modes (`center` → gnomonic, `antipode` → stereographic, `infinity` → parallel orthographic beams arriving along the **radial** normal, `math` → centre beams). `computeAuxSurfaceParams` takes the full projection descriptor. The cylinder is equatorial and always touches the globe (axis through the poles). `clampLocalToSurface(surface, p)` then clamps every ray endpoint to the rendered surface's finite extent so a ray can never fly into empty space (exposed via `computeConicRayEnd(..., clamp=true)` for tests). `AuxSurface.tsx` calls `computeAuxSurfaceParams` with the same full param set so the wireframe and the rays share identical sizing, and `Rays.tsx` draws the hover ray as a polyline `start→globe→end` so the yellow globe marker lies exactly on the beam.
- Visualization methods (3D scene) are selected by `vizMethod` in the store and rendered by `VizMethodRenderer.tsx`: `none`, `normals` (`PerpendicularNormals.tsx`), `particles` (`ParticleTransfer.tsx`), `magnetic` (`MagneticField.tsx`), `peel` (`PeelOff.tsx`), `wave` (`WaveProjection.tsx`), `laser` (`LaserScanner.tsx`), `construction` (`GeometricConstruction.tsx`), `shadow` (`ShadowPlay.tsx`). `CutLine.tsx` draws the developable-surface cut/peel line; `TouchPointPin.tsx` marks the azimuthal touch point. `CircularSlider.tsx` is a circular drag control (used for e.g. gamma / tilt); `Toggle.tsx` is a generic on/off switch; `ui/Badge.tsx` is a small label helper.
- `src/utils/tissot.ts` builds the Tissot indicatrices for the 2D `Map2D` overlay: `computeTissotCircles(density)` returns an array of 5°-radius spherical circles (`d3Geo.geoCircle().radius(5)`) on a `density`-degree lon/lat grid (default 30°), staggered by half a step on every other latitude row so the pattern is even. `Map2D` passes the store's `graticuleStep` as `density` so the indicatrices line up with the visible graticule. Used only when `showTissot` is on.
- `src/constants/designTokens.ts` exports the shared palette `NEON_BLUE` / `NEON_ORANGE` / `NEON_YELLOW` / `NEON_WHITE` / `BG` and the new visualization tokens `NEON_GREEN`, `NEON_RED`, `PARTICLE_COLOR`, `WAVE_COLOR`, `LASER_COLOR`, `NORMAL_COLOR`; both 2D and 3D components import it instead of hard-coding the hex values. `src/constants/geometry.ts` holds shared numeric constants (`MAP_SCALE`, `VIEW_CENTER_X/Y`, `CLIP_LAT`, `FIT_MARGIN`, `RADIUS`, `RAY_COUNT`, aux-surface factors, `STD_PARALLEL_MIN_ABS` / `STD_PARALLEL_FALLBACK`) plus the new UTM / Earth / circle-radius / SOM helpers: `UTM_ZONE_WIDTH`, `UTM_ZONE1_MERIDIAN`, `UTM_TOTAL_ZONES`, `EARTH_RADIUS_KM`, `EARTH_HALF_CIRCUM_KM`, `CIRCLE_RADIUS_MIN` / `CIRCLE_RADIUS_MAX`, `SOM_INCLINATION_MIN` / `SOM_INCLINATION_MAX`, `SOM_PERIOD_MIN` / `SOM_PERIOD_MAX`, and the helpers `utmZoneToCentralMeridian`, `centralMeridianToUtmZone`, `circleRadiusToScale`, `scaleToCircleRadius`, `k0ToStandardParallel`, `standardParallelToK0` — single source so magic numbers never drift between the 2D map and the 3D scene.
- `src/store/selectors.ts` exposes `useProjectionParams()` (a memoized `ProjectionParams` slice) so consumers read the projection state as one object instead of subscribing to every field. `GlobeScene` and `Map2D` use it.
- `src/components/ui/` holds shared styling extracted from `ControlPanel`: `icons.tsx` (all SVG icons), `styles.ts`, `labels.ts`, the helper `Badge.tsx`, and the reusable controls `ParamSlider.tsx` (labelled range slider with value readout + disabled/locked state) and `PresetChips.tsx` (a row of active/inactive preset buttons). Keep cross-component UI here, not in a component file, to avoid `react-refresh` export warnings.
- `src/components/ProjectionCatalog.tsx`: modal rendered via `createPortal` to `document.body` listing all 14 projections grouped by the four families with text search. Selecting a row calls `setVariant(variant)` and closes.
- `src/components/GlobeScene.tsx` passes the computed `surface` object down to `AuxSurface`, `IntersectionDisks` and `LightSource`, so all three share one computation and can never drift apart. For the `azimuthalMath` (analytic, no-light) family the `LightSource` and `Rays` are not rendered.
- `src/components/Dropdown.tsx` is a generic `Dropdown<T extends string>` (a `button` + popover, variants `button` / `inline`) — it backs the math-model selector in `ControlPanel.tsx` and the EPSG-filter selects in `EpsgCatalog.tsx`. It is unit-tested (`Dropdown.test.tsx`).
- `src/components/EpsgCatalog.tsx`: modal rendered via `createPortal` to `document.body` (so it isn't trapped by the panel's `backdrop-blur` containing block). Selecting a row calls `applyPreset(row.params)` and closes.
- `src/components/ProjectionSummary.tsx`: the read-only **Геодетическая сводка** (Geodetic Summary) modal opened by the **ℹ️ Точные параметры** button in `ControlPanel.tsx`; lists λ₀, φ₀, φ₁, φ₂, scale, γ, `falseEasting`, `falseNorthing` and the computed projection class. Mirror of `EpsgCatalog`'s modal styling.
- `src/components/ErrorBoundary.tsx`: a React class error boundary (the only way to catch a child's render-time throw) wrapping `GlobeScene` in `App.tsx`. When the WebGL `<Canvas>` is unavailable (old browser, GPU disabled, no driver, admin policy) it renders a friendly Russian fallback panel («3D-глобус недоступен … 2D-карта справа продолжает работать») instead of crashing to a white screen. The 2D `Map2D` (pure SVG, no WebGL) keeps working in any case. Unit-tested in `ErrorBoundary.test.tsx`.
- Note: `IntersectionDisks` component (previously `TangencyRings`) draws the neon-green rings where the aux surface meets the globe.

## Store shape (verified in code)
ProjectionParams (the param slice of the store, type `ProjectionParams`):
```ts
variant: ProjectionVariant;  // named projection variant — determines family/distortion/azLight
family: 'cylindrical' | 'conic' | 'azimuthalPerspective' | 'azimuthalMath';
distortion: 'conformal' | 'equalArea' | 'equidistant';
lambda0: number;       // -180...180  central meridian
phiOrigin: number;     // -90...90    central latitude
scaleFactor: number;   // 0.9...1.1 (conic/azimuthal); 0.5...1.0 cylindrical (1.0 = cylinder diameter = Earth's, 0.5 = half)
falseEasting: number;  // -1000...1000
falseNorthing: number; // -1000...1000
gamma: number;         // -180...180  tilt / 3rd rotation → oblique & transverse aspects
stdParallel2: number | null;          // φ2; null = tangent surface (single standard parallel)
azLight: 'center' | 'antipode' | 'infinity' | 'math';   // azimuthal light-source mode

// Ruler (distance measurement) state
rulerMode: 'off' | 'first' | 'second' | 'done';
rulerPoint1: [number, number] | null;
rulerPoint2: [number, number] | null;

// UTM zone (Transverse Mercator) — overrides lambda0 when set
utmZone: number | null;

// Vertical / tilted perspective satellite parameters
azHeight: number;    // km, 100–1500000
azTiltDeg: number;   // degrees, 0–89
azAzimuthDeg: number;// degrees, 0–360

// Cone hemisphere (north / south)
coneHemisphere: 'north' | 'south';

// Sun-synchronous orbit (SOM) parameters for oblique Mercator
somInclination: number;  // degrees, 0–180
somPeriod: number;       // minutes, 1–1440
somNodeLongitude: number;// degrees

// Test-circle radius (km) for azimuthal-math projections
circleRadiusKm: number;  // 1000–20000
```
Non-param state (also on the store):
```ts
showTissot: boolean;
showBorders: boolean;                 // 2D country-border layer toggle (default false)
showIntersection: boolean;            // 2D white lines where the aux surface meets the globe (default false; the 3D scene always draws them)
geoJsonData: FeatureCollection | null;      // land-110m, source for the 3D globe
land50GeoJson: FeatureCollection | null;    // land-50m, 2D base map
countriesGeoJson: FeatureCollection | null; // countries-50m, 2D border layer (detailed mode)
countries110GeoJson: FeatureCollection | null; // countries-110m, 2D border layer (lightweight mode)
detailedMap: boolean;                       // 2D map detail toggle (default false → lightweight 110m land + 110m borders; true → 50m land + 50m borders)
geoLoading: boolean;                        // true while loadGeoData fetches the bundled geodata
geoDataError: string | null;                // friendly Russian message set when BOTH the 110m and 50m land fetches fail (null otherwise); Map2D shows it in the empty-map overlay so the user knows to reload
hoverLonLat: [number, number] | null;  // hovered (lon, lat), shared so the other view mirrors the highlight
hoverSource: 'globe' | 'map' | null;   // which view set hoverLonLat (ray drawn only for 'map')
showHoverRay: boolean;                 // cursor projection ray in the 3D scene, shown only while the 2D map is hovered (default false)

// Non-parametric visualization / interaction state
vizMethod: 'none' | 'normals' | 'particles' | 'magnetic' | 'peel' | 'wave' | 'laser' | 'construction' | 'shadow';
showHeatmap: boolean;
heatmapType: 'area' | 'angle' | 'scale';
graticuleStep: 1 | 5 | 10 | 15 | 30;
showGraticule: boolean;
testFigureType: 'circles' | 'squares' | 'faces' | null;
showRays: boolean;
rulerActive: boolean;
unfoldTrigger: boolean;
```
Map data is bundled locally (no runtime/external API, per spec): `public/world-110m.topojson` (Natural Earth 1:110m land, used by the 3D globe), plus `public/land-50m.json` and `public/countries-50m.json` (1:50m, used by the 2D `Map2D`). All three files are **TopoJSON** (`{type:'Topology'}` with `objects.land` / `objects.countries`); despite the `.json` extension they are parsed via `topojson-client`'s `feature()`, not fetched as GeoJSON. `loadGeoData` fetches all three in parallel and stores them separately; a failed fetch for one file does not abort the others. A monotonic `_geoToken` discards stale results if a newer fetch starts before an older one resolves (so a fast remount can't overwrite fresh data with stale data). If BOTH the 110m and 50m land fetches fail the 2D map has nothing to render and `geoDataError` is set to a friendly Russian message («Не удалось загрузить карту. Проверьте подключение к интернету и перезагрузите страницу.»); `Map2D` shows it in its empty-map overlay (no retry button — the user reloads the page). A partial failure (any single file) stays silent because the surviving layers still produce a usable map. As of the 110m-borders change it also loads `public/countries-110m.json` (Natural Earth 1:110m Admin 0) into `countries110GeoJson`. The lightweight 2D map now draws 110m borders (`countries110GeoJson`), while the detailed map keeps 50m borders (`countriesGeoJson`); the **Границы стран** button is always visible and toggles a real border layer in both lightweight and detailed modes. `isEllipsoid` was removed — the model is **spherical** (D3 projections are spherical too; true ellipsoidal support is out of scope).

## Hard rules / conventions (from spec, enforced in code)
- Strict TypeScript: no `any` in component props; type the TopoJSON `FeatureCollection`.
- Wrap D3 projection / `pathGenerator` / ray math in `useMemo` — real-time perf requirement, never recompute per frame.
- All controls are always visible — when a parameter is locked by the selected projection variant it shows as **disabled** (not hidden), with `🔒` prefix and the locked value. The visual/physical params each have a dedicated control, labeled with the **physical terms** of the projection; controls are **context-dependent** (some shown only for certain variants, e.g. UTM zone for Transverse Mercator, parallel 2 for secant cones, k₀ / standard-parallel link for cylindrical, north/south hemisphere for conic, satellite height/tilt/azimuth for the perspective variants, touch-point presets for azimuthal, circle radius for azimuthal-math, orbital params for oblique Mercator). The **Тип искажения** (`distortion`) is set implicitly via the variant dropdown. A separate **ℹ️ Точные параметры** button opens a read-only Geodetic Summary **modal** listing λ₀, φ₀, φ₁, φ₂, scale, γ, and the computed projection class. The top row shows a **Выбрать проекцию** button (opens the full projection catalog grouped by the four families) plus the **ℹ️ Точные параметры** and **Сбросить** buttons sharing one rectangular neon style.
- Earth model is spherical; do not add ellipsoid math.
- Per spec §9.3, WebGL/`<Canvas>` and SVG `d` attributes are intentionally **not** unit-tested. Existing unit tests cover the store, `projectionMapper`, `auxSurfaceGeometry`, `ControlPanel`, `Map2D`, `EpsgCatalog`, `Dropdown`, `ErrorBoundary`, and `App`.

## Gotchas an agent will likely miss
- **Native `<select>` popups ignore CSS `background` on most browsers (they render white).** The app uses a single custom dark dropdown `src/components/Dropdown.tsx` (a `button` + popover, variants `button` / `inline`) — it backs the math-model selector in `ControlPanel.tsx` and the EPSG-filter selects in `EpsgCatalog.tsx`. It is generic over the option value type. Do NOT replace it with a native `<select>` — keep it custom so the dark theme holds.
- `falseEasting` / `falseNorthing` exist in the store and projection math but have **no sliders in the UI** (only `lambda0`, `phiOrigin` [conic/azimuthal], `scaleFactor` are exposed). Don't assume they're wired to controls.
- The four family buttons in `ControlPanel` are a single segmented control (overlapping borders via `-ml-px`, `z-10` on the active one) — keep the segmented look when editing.

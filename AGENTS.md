# AGENTS.md

## Project status
Working MVP of «Carto-Space» — an interactive cartographic-projection simulator (educational tool showing the 3D Earth ↔ 2D map relationship). Client-side SPA only: **no backend, no external APIs**; all projection math runs in-browser. Product/legacy specs live in `docs/BRD.md` (business, Russian) and `docs/specification.md` (technical, Russian) — they may be out of date; **this `AGENTS.md` is the authoritative implementation reference.** The app UI language must be Russian.

## Commands
Run **directly from the project directory** `/mnt/d/_projects/pet_project/map_project_browser`:
- `npm run dev` — Vite dev server
- `npm run build` — `tsc -b && vite build` (typecheck + production build)
- `npm run lint` — ESLint
- `npm run test` — Vitest (`vitest run`); `npm run test:watch` for watch mode
- `npm run preview` — preview the built app

Typecheck is part of `build` (`tsc -b`); there is no separate `typecheck` script. `lint` runs before `build` in CI, so lint errors fail the build there.

## Dev workspace / DrvFS workaround (CRITICAL)
`/mnt/d` is a Windows-mounted drive (9P/DrvFS). `npm install` fails there with `ENOTDIR` on `mkdir node_modules`, and a corrupted `node_modules` dentry cannot be removed from inside the container. We keep a real `node_modules` on the **native Linux filesystem** and symlink it into the project:
- Native home for deps lives on the **persistent** WSL filesystem (NOT `/tmp`, which is wiped on every reboot): `~/mbp-deps/node_modules`, created via `npm ci` inside `~/mbp-deps` (that dir also holds `package.json` + `package-lock.json`). Use the WSL home of whichever user runs the build — typically `/home/<user>/mbp-deps`.
- In the project dir, `node_modules` is a symlink → `~/mbp-deps/node_modules` (the symlink itself lives on the Windows disk under `/mnt/d`, so it survives reboots too). `eslint.config.js` is a real native copy (or symlink). No other source/config symlinks are needed.
- `vite.config.ts` sets `server.watch.usePolling` because DrvFS emits no `inotify` events, so Vite's watcher otherwise never sees edits under `/mnt/d` (HMR won't fire). No `preserveSymlinks` is needed — sources are local.

Because the native deps and the project symlink are both persistent, **no setup is needed after a reboot** — just `npm run dev` from WSL. The one-time setup (run once from WSL): `H=~/mbp-deps; mkdir -p "$H" && cp package.json package-lock.json "$H"/ && cd "$H" && npm ci`, then `ln -sfn "$H/node_modules" /mnt/d/_projects/pet_project/map_project_browser/node_modules`. Only re-run this if the symlink/target is ever deleted. **Do NOT run `npm install`/`npm ci` inside `/mnt/d`.**

## Architecture (how it is wired)
- Single Zustand store `src/store/useAppStore.ts` is the **only** source of truth; UI / 2D / 3D components only read from it or call its actions (`setParam`, `setShowTissot`, `setFamily`, `resetParams`, `applyPreset`, `loadGeoData`). `setFamily(family)` switches the projection class **and resets all params to the family defaults** (`lambda0=0, phiOrigin=0, scaleFactor=1, falseEasting=0, falseNorthing=0, gamma=0, stdParallel2=null, azLight='math'`, plus the family-default `distortion`). `resetParams()` does the same reset for the *current* family without changing the family. Default distortion per family (exported as `DEFAULT_DISTORTION`, see `defaultParamsForFamily`): cylindrical → conformal, conic → equidistant, azimuthal → equal-area.
- `src/utils/projectionMapper.ts` maps (`family` × `distortion`) → a D3 projection, then applies `proj.rotate([-lambda0, -phiOrigin, -gamma]).scale(MAP_SCALE * scaleFactor).translate([VIEW_CENTER_X + falseEasting, VIEW_CENTER_Y + falseNorthing])` (constants from `constants/geometry.ts`; `MAP_SCALE=100`, `VIEW_CENTER_X=400`, `VIEW_CENTER_Y=300`). Note the **negative** rotation signs; the third rotation component `gamma` yields oblique / transverse aspects. For the **cylindrical** family the diameter (`scaleFactor`) is the cylinder radius R·`scaleFactor`; the cylinder meets the globe at the contact parallels ±arccos(`scaleFactor`), which are the projection's **standard parallels** (true scale). Conformal (Mercator) is the unique conformal cylindrical projection, hence shape-invariant to the diameter — there it is just a scale; equal-area / equidistant instead set their standard parallel to the contact (x ∝ `scaleFactor`, y ∝ 1/`scaleFactor`), so the unrolled map's **aspect genuinely changes** with the diameter (a smaller cylinder → a narrower / taller map) — the real geometric effect, which `fitProjectionToView` preserves by fitting the globe to the viewport (object-fit: contain), so the diameter shows through the projection's aspect rather than its size. The azimuthal family's projection is selected by `azLight` (the interactive light source): `center` → `geoGnomonic`, `antipode` → `geoStereographic`, `infinity` → `geoOrthographic`, `math` → the `distortion`-selected analytic projection (equal-area / equidistant; conformal azimuthal is itself stereographic). Conic projections use `parallels([phi1, phi2])` where `phi1 = signedStandardParallelDeg(phiOrigin)` keeps `phiOrigin`'s *sign* (so a southern `phiOrigin` yields a southern standard parallel matching the 3D aux cone; falls back to `±30°` when `|phiOrigin| < 10`), and `phi2 = stdParallel2` when set (secant cone) or `phi1` (tangent). The 3D cone geometry derives the parallel *magnitude* via the shared `standardParallelDeg` helper and the hemisphere from the sign of `phiOrigin`, so the 2D map and the 3D aux surface always agree on where the cone touches the globe. `fitProjectionToView` overrides scale/translate to fit the 2D map to its container (the fixed `scale(100)` is only used by the 3D ray math). It fits a **clipped ±85° sphere** (`FIT_SPHERE`) to the viewport, NOT a full `{type:'Sphere'}`: for `geoConicConformal` the pole maps to infinity, so a full-Sphere `fitExtent` collapses the scale to near-zero (the globe renders as an empty half-disk). The clip keeps the fitted scale finite. Because the map is always fitted to fill the viewport (`object-fit: contain`), the cylinder diameter is NOT visible as a size change — the map occupies the full area for every `scaleFactor`; the diameter shows through the projection's aspect (equal-area / equidistant narrow as the cylinder shrinks) and through the 3D / Tissot intersection rings and the `Искажение площади` number. Conformal (Mercator) is shape-invariant to the diameter, so its 2D map is unchanged by `scaleFactor`; only the rings / Tissot / number move. For conic/azimuthal `scaleFactor` is a plain zoom, but the fitted map still always fills the viewport. (For `azLight='infinity'` the 2D map becomes an orthographic hemisphere view, by design.)
- 2D `src/components/Map2D.tsx`: responsive SVG (measures its container via `ResizeObserver`) whose projection is fitted with `fitProjectionToView`; graticule, coastlines from `land50GeoJson` (≥50m detail), optional country-border layer from `countriesGeoJson`, and optional Tissot indicatrices via `d3Geo.geoCircle().radius(5)` on a 30° grid. The globe always fills the viewport (with a small uniform margin) for every `scaleFactor`, fitted to the container preserving the projection's own aspect ratio (`object-fit: contain`). The cylinder diameter (cylindrical) is therefore NOT visible as a 2D size change — it shows through the map's aspect (equal-area / equidistant narrow as the cylinder shrinks) and through the 3D / Tissot intersection rings and the `Искажение площади` number. Conformal (Mercator) is shape-invariant to the diameter, so its 2D map is unchanged by `scaleFactor`; only the rings / Tissot / number move. (For `azLight='infinity'` the 2D map becomes an orthographic hemisphere view, by design.) The **Индикатрисы Тиссо**, **Детализация карты** and **Границы стран** buttons are always visible together as a single horizontal row in the map's top-right corner. When detail is off, `Map2D` draws the lightweight 110m `geoJsonData` land with 110m borders (`countries110GeoJson`) instead of the 50m datasets. The map's **bottom-right corner** shows a small glass label `Искажение площади: NN%` — the area-weighted area distortion of the current projection settings, computed by `computeAreaDistortion` (in `projectionMapper.ts`): it samples local area-scale factors on a fine lon/lat grid and reports the mean relative area excess (equal-area projections → ~0%). The 100% reference is the area scale **at the standard parallel (where true scale = 1)**. For the cylindrical family the standard parallels are the surface–globe intersections at ±arccos(`scaleFactor`) (a tangent cylinder is the single-intersection limit at `scaleFactor` = 1), so an immersed (secant) cylinder — two intersections — makes the distortion **drop** as the cylinder diameter shrinks, matching the 3D intersection rings; conic/azimuthal treat `scaleFactor` as a true zoom and reference the projection centre. Cells that straddle the antimeridian, fold onto themselves, or are stretched far past the centre scale (projection discontinuities) are skipped so they can't masquerade as distortion. The map's **bottom-left corner** carries a neon link to the Stepik course «Геопространственный анализ данных на Python» (https://stepik.org/a/258792).
- 3D scene `src/components/GlobeScene.tsx` composes five thin components (all flat under `components/`, no `Scene3D/` subfolder): `Globe.tsx` (transparent dark sphere with neon-blue **3D-line** coastlines + graticule — NOT the `CanvasTexture`/orthographic variant from spec §6), `AuxSurface.tsx` (fully transparent neon-orange **wireframe** of the developable surface — its own meridians + parallels; cylinder for cylindrical, cone for conic, plane for azimuthal; the azimuthal plane is the projection plane tangent to the globe), `IntersectionDisks.tsx` (hollow white neon rings marking the **actual** intersection of the aux surface with the globe — 0, 1 or 2 circles; a cylinder of radius R·scaleFactor yields two circles when immersed, one when tangent, none when it encloses the sphere; the component renders nothing when the surface does not touch the globe), `LightSource.tsx` (the projection's **light source** — a point lamp at the globe centre/antipode for azimuthal, and the conic apex marker; nothing is drawn for the cylindrical family since the globe is simply unrolled onto the cylinder), and `Rays.tsx` (yellow light-beam fan showing the projection: each ray runs from the light source, through the point on the globe at the central meridian, to the point where that globe point lands on the **auxiliary surface** — the unrolled surface IS the 2D map). The fan is **analytic** (computed by `computeCentralMeridianRays` in `auxSurfaceGeometry.ts`): the source is the globe centre for cylindrical / azimuthal-`center` / conic-apex, the antipode for azimuthal-`antipode`, and a parallel beam along the radial normal for azimuthal-`infinity`; every ray endpoint is placed with `auxPointToWorld` so it coincides exactly with `AuxSurface`'s wireframe, and small neon markers sit at the globe point and at the surface landing. It renders with `depthTest={false}` so the in-globe portion stays visible, and as **dashed** formula vectors in `math` mode; it renders independently of whether the geo dataset has loaded. Hovering the **2D map** (with `showHoverRay` on) draws the cursor projection ray via `projectToAuxWorld` and the shared yellow highlight marker on both views — directly showing the “globe point → map point” link (the aux surface, unrolled, is the 2D map). Hovering the **3D globe** does **not** draw the ray or the marker at all (the hover highlight is driven solely by the 2D map). `GlobeScene` adds `OrbitControls` (from `@react-three/drei`, `makeDefault`, pan disabled) so the user can rotate/zoom the camera and see the aux surface's true 3D orientation — without it, a tangent plane on the visible hemisphere always appears to face the viewer. The azimuthal aux-plane wireframe rotates its grid points directly by the tangent-basis quaternion (not via the group `quaternion` prop) so its orientation is always correct. `LightSource` also renders a small `Html` label next to the marker naming the active light mode (Центр / Антипод / ∞ / Вершина конуса). The 2D map (`Map2D.tsx`) and the 3D globe share a **hover linkage**: hovering either view reads the (lon, lat) under the cursor (`proj.invert` for the SVG, `vec3ToLonLat` for the 3D pick-sphere) into the store's `hoverLonLat` and the other view draws a matching yellow marker, so a point is cross-highlighted across both projections.
- `src/utils/auxSurfaceGeometry.ts` is the **single source of truth** for all 3D geometry: `computeAuxSurfaceParams`, `computeAuxGraticule`, `computeTangencyRing`, `computeAuxSphereIntersections` (the real aux-surface↔globe intersection circles), `auxPointToWorld` (the single world-transform for the aux surface, shared by `AuxSurface` and the rays so they can never drift), `computeCentralMeridianRays` (the central-meridian ray fan) and `projectToAuxWorld` (the per-point ray used by the hover demo), `computeTangentBasis`, `lonLatToVec3` (`RADIUS = 10`). Surface, ring, and rays derive from the same math so they can never drift apart. (Replaces the old `rayGeometry.ts`.) `computeCone(phi1, phi2, radius, scaleFactor)` supports both **tangent** (φ1 = φ2) and **secant** (φ1 ≠ φ2, same hemisphere) cones; the cone sits in the **signed** hemisphere of `phiOrigin` (so a southern `phiOrigin` yields a south-pointing cone) while the parallel *magnitude* uses the equatorial `30°` fallback on `|phiOrigin|`. `gamma` (stored in **degrees** in the store) tilts the cylinder/cone/plane for oblique & transverse aspects — it is converted to radians inside this module (`gammaRad`) and inside `AuxSurface.tsx` (Three.js rotations are radians), so the rays and the wireframe stay aligned. `computeCentralMeridianRays` honours the azimuthal `azLight` modes (`center` → gnomonic, `antipode` → stereographic, `infinity` → parallel orthographic beams arriving along the **radial** normal, `math` → centre beams rendered as dashed formula vectors). `computeAuxSurfaceParams` now takes the full projection descriptor (`distortion`, `azLight` in addition to family/λ₀/φ₀/scale/φ₂/γ). The **cylinder is equatorial and always touches the globe** (axis through the poles); `phiOrigin` chooses which parallel is centred on the 2D map / the standard parallel, but the cylinder does **not** translate in 3D. Its **height depends on the distortion + diameter** (a different `Тип искажения` yields a different-looking cylinder). The **azimuthal plane disk** is sized from the actual D3 projection of the fitted ±`CLIP_LAT` band (so a Mercator/equirectangular/gnomonic map — which sends high latitudes far out — still has a surface big enough for every ray to land on), capped at `AUX_SIZE_CAP · AUX_LENGTH · radius` (`AUX_SIZE_CAP = 4`) so a gnomonic disk that runs to infinity stays finite. `clampLocalToSurface(surface, p)` then clamps every ray endpoint to the rendered surface's finite extent so a ray can never fly into empty space: cylinder → local Y within `±height/2`; **cone → radially scaled toward the apex** (so the endpoint stays *on the lateral surface* — a naive Y-clamp would flatten the cone into a cap and break the geometry); plane → radial distance within `size/2`. The clamp is applied inside **both** `computeCentralMeridianRays` and `projectToAuxWorld` (and exposed via `computeConicRayEnd(..., clamp=true)` for tests). `AuxSurface.tsx` calls `computeAuxSurfaceParams` with the same full param set so the wireframe and the rays share the identical sizing, and `Rays.tsx` draws the hover ray (like every ray in the static fan) as a polyline `start→globe→end` so the yellow globe marker lies exactly on the beam, and the "globe point → map point" link is explicit (the aux surface, unrolled, is the 2D map).
- `src/constants/designTokens.ts` exports the shared palette `NEON_BLUE` / `NEON_ORANGE` / `NEON_YELLOW` / `NEON_WHITE` / `BG`; both 2D and 3D components import it instead of hard-coding the hex values. `src/constants/geometry.ts` holds shared numeric constants (`MAP_SCALE`, `VIEW_CENTER_X/Y`, `CLIP_LAT`, `FIT_MARGIN`, `RADIUS`, `RAY_COUNT`, aux-surface factors, `STD_PARALLEL_MIN_ABS` / `STD_PARALLEL_FALLBACK`) and the deduplicated `standardParallelDeg` helper — single source so magic numbers never drift between the 2D map and the 3D scene.
- `src/store/selectors.ts` exposes `useProjectionParams()` (memoized `ProjectionParams` slice) and `useGeoData()` so consumers read the projection state as one object instead of subscribing to every field. `GlobeScene` and `Map2D` use these.
- `src/utils/threeHelpers.ts` holds `quatFromNormal` (the quaternion that rotates +Z onto a normal), shared by `AuxSurface` and `IntersectionDisks` (was duplicated inline). `AuxSurface` and `IntersectionDisks` now memoize their geometry (`computeAuxSurfaceParams` / `computeAuxGraticule` / `computeTangencyRing`) to match the `Rays` precedent and the "wrap D3/ray math in `useMemo`" hard rule.
- `src/components/ui/` holds shared styling extracted from `ControlPanel`: `icons.tsx` (all SVG icons), `styles.ts` (`panelClass`, `labelClass`, `activeTab`, `inactiveTab`, `iconBtn`), and `labels.ts` (the Russian `FAMILY_*` / `DISTORTION_*` option lists + label maps, previously duplicated in `ControlPanel` and `EpsgCatalog`). Keep cross-component UI here, not in a component file, to avoid `react-refresh` export warnings.
- `src/components/Dropdown.tsx` is a generic `Dropdown<T extends string>` (a `button` + popover, variants `button` / `inline`) — it backs the math-model selector in `ControlPanel.tsx` and the EPSG-filter selects in `EpsgCatalog.tsx`. It is unit-tested (`Dropdown.test.tsx`).
- `src/components/EpsgCatalog.tsx`: modal rendered via `createPortal` to `document.body` (so it isn't trapped by the panel's `backdrop-blur` containing block). Selecting a row calls `applyPreset(row.params)` and closes.
- `src/components/ProjectionSummary.tsx`: the read-only **Геодетическая сводка** (Geodetic Summary) modal opened by the **ℹ️ Точные параметры** button in `ControlPanel.tsx`; lists λ₀, φ₀, φ₁, φ₂, scale, γ and the computed projection class. Mirror of `EpsgCatalog`'s modal styling.

## Store shape (verified in code)
```ts
family: 'cylindrical' | 'conic' | 'azimuthal';
distortion: 'conformal' | 'equalArea' | 'equidistant';
lambda0: number;       // -180...180  central meridian
phiOrigin: number;     // -90...90    central latitude
scaleFactor: number;   // 0.9...1.1 (conic/azimuthal); 0.5...1.0 cylindrical (1.0 = cylinder diameter = Earth's, 0.5 = half)
falseEasting: number;  // -1000...1000
falseNorthing: number; // -1000...1000
gamma: number;         // -180...180  tilt / 3rd rotation → oblique & transverse aspects
stdParallel2: number | null;          // φ2; null = tangent surface (single standard parallel)
azLight: 'center' | 'antipode' | 'infinity' | 'math';   // azimuthal light-source mode
showTissot: boolean;
showBorders: boolean;                 // 2D country-border layer toggle (default false)
showIntersection: boolean;            // 2D white lines where the aux surface meets the globe (default false; the 3D scene always draws them)
hoverLonLat: [number, number] | null;  // hovered (lon, lat), shared so the other view mirrors the highlight (spec §2)
hoverSource: 'globe' | 'map' | null;   // which view set hoverLonLat (ray drawn only for 'map')
showHoverRay: boolean;                 // cursor projection ray in the 3D scene, shown only while the 2D map is hovered (default false)
geoJsonData: FeatureCollection | null;      // land-110m, source for the 3D globe
land50GeoJson: FeatureCollection | null;    // land-50m, 2D base map
countriesGeoJson: FeatureCollection | null; // countries-50m, 2D border layer (detailed mode)
countries110GeoJson: FeatureCollection | null; // countries-110m, 2D border layer (lightweight mode)
detailedMap: boolean;                       // 2D map detail toggle (default false → lightweight 110m land + 110m borders; true → 50m land + 50m borders)
```
Map data is bundled locally (no runtime/external API, per spec): `public/world-110m.topojson` (Natural Earth 1:110m land, used by the 3D globe), plus `public/land-50m.json` and `public/countries-50m.json` (1:50m, used by the 2D `Map2D`). All three files are **TopoJSON** (`{type:'Topology'}` with `objects.land` / `objects.countries`); despite the `.json` extension they are parsed via `topojson-client`'s `feature()`, not fetched as GeoJSON. `loadGeoData` fetches all three in parallel and stores them separately; a failed fetch for one file does not abort the others. As of the 110m-borders change it also loads `public/countries-110m.json` (Natural Earth 1:110m Admin 0, redistributed via `topojson/world-atlas`) into `countries110GeoJson`. The lightweight 2D map now draws 110m borders (`countries110GeoJson`), while the detailed map keeps 50m borders (`countriesGeoJson`); the **Границы стран** button is always visible and toggles a real border layer in both lightweight and detailed modes. `isEllipsoid` was removed — the model is **spherical** (D3 projections are spherical too; true ellipsoidal support is out of scope for the MVP).

## Hard rules / conventions (from spec, enforced in code)
- Strict TypeScript: no `any` in component props; type the TopoJSON `FeatureCollection`.
- Wrap D3 projection / `pathGenerator` / ray math in `useMemo` — real-time perf requirement, never recompute per frame.
- All controls visible at once (no hidden/nested control levels). The visual/physical params each have a dedicated control in `ControlPanel.tsx`, labeled with the **physical terms** of the projection and grouped per family (e.g. cylindrical shows **Диаметр цилиндра** = `scaleFactor`, **Центральная широта (φ₀)** = `phiOrigin`, **Поворот вокруг Земли** = `lambda0`, **Угол наклона цилиндра** = `gamma`; conic shows **Угол при вершине**, **Положение вершины (φ₂)** = `stdParallel2`, **Вращение конуса** = `lambda0`; azimuthal shows **Точка касания** = `lambda0`/`phiOrigin`, **Расстояние до плоскости** = `scaleFactor`, **Вращение плоскости** = `gamma`). The **Тип искажения** (distortion) selector and the **Источник света** dropdown (azimuthal only: `center`/`antipode`/`infinity`/`math`) sit alongside. A separate **ℹ️ Точные параметры** button opens a read-only Geodetic Summary **modal** (mirroring the EPSG-catalog modal) listing λ₀, φ₀, φ₁, φ₂, scale, γ, and the computed projection class. The three top-right header buttons (Библиотека EPSG, Точные параметры, Сбросить) share one rectangular neon style and are never shown in a highlighted/active state by default. The dropdown reuses the shared custom `Dropdown<T>`; its Russian option list lives in `src/components/ui/labels.ts` (`AZIMUTHAL_LIGHT_OPTIONS`). `falseEasting` / `falseNorthing` remain in the store/projection math but still have no UI sliders.
- Earth model is spherical; do not add ellipsoid math.
- Per spec §9.3, WebGL/`<Canvas>` and SVG `d` attributes are intentionally **not** unit-tested. Existing unit tests cover the store, `projectionMapper`, `auxSurfaceGeometry`, `ControlPanel`, `Map2D`, `EpsgCatalog`, `Dropdown`, and `App`.

## Gotchas an agent will likely miss
- **Native `<select>` popups ignore CSS `background` on most browsers (they render white).** The app uses a single custom dark dropdown `src/components/Dropdown.tsx` (a `button` + popover, variants `button` / `inline`) — it backs the math-model selector in `ControlPanel.tsx` and the EPSG-filter selects in `EpsgCatalog.tsx`. It is generic over the option value type. Do NOT replace it with a native `<select>` — keep it custom so the dark theme holds.
- `falseEasting` / `falseNorthing` exist in the store and projection math but have **no sliders in the UI** (only `lambda0`, `phiOrigin`, `scaleFactor` are exposed). Don't assume they're wired to controls.
- The three family buttons in `ControlPanel` are a single segmented control (overlapping borders via `-ml-px`, `z-10` on the active one) — keep the segmented look when editing.
- The EPSG modal is a fixed `920px × 80vh` with `table-fixed` + `<colgroup>` so column widths never shift when filtering. Keep fixed widths when editing that table.
